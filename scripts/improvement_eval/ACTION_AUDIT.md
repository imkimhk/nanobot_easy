# 행동 감사 기록

`tools.actionAudit.enabled`는 기본값 `false`다. 활성화한 워크스페이스의
`.audit/actions.sqlite3`에만 실행 시도·관찰된 결과·스킬 승인 상태를 남긴다.
모델 호출, 도구 스키마, 실행 권한, 기존 승인 절차는 변경하지 않는다.

```json
{"tools": {"actionAudit": {"enabled": true, "maxRecords": 10000}}}
```

게이트웨이 설정을 변경하고 다음 정상 기동부터 활성화한다. 여러 게이트웨이의
설정을 자동으로 바꾸거나 재시작하지 않는다. 끄려면 `enabled`를 `false`로 되돌린다.
기존 기록은 유지되며 새 기록을 추가하지 않는다.

## 조회

```bash
.venv/bin/nanobot audit list --workspace /path/to/workspace --limit 30
.venv/bin/nanobot audit list --workspace /path/to/workspace --status blocked --json
```

`--session`에 기존 세션 키를 지정하면 해당 대화만 조회한다. 워크스페이스는
반드시 명시한다. 조회는 읽기 전용이며, 기록이 없다고 DB나 설정을 만들지 않는다.
선택된 최근 기록을 시간순으로 보여준다.

## 무엇을 뜻하는가

| 상태 | 확인된 사실 |
| --- | --- |
| attempted | 도구 실행에 들어가기 전 시도 기록. 실행 여부·완료는 아직 불명 |
| tool_ok | 도구가 정상 결과를 반환함. 최종 업무 완료·외부 전달·사용자 승인의 증거는 아님 |
| blocked | 실행 전 검사에서 거절했거나 기존 차단 이벤트가 발생함 |
| superseded | 후속 지시로 기존 시도가 대체됨 |
| error | 오류 결과가 관찰됨. 부작용이 없거나 복원되었다는 뜻은 아님 |
| unknown | 중단·결과 불명. 실제 변경이 남았을 수 있음 |
| approved / rejected | 기존 스킬 승인 절차의 등록 성공 / 명시적 취소·거절 |
| approval_failed | 채팅의 정확한 승인 응답을 처리했으나 실제 등록은 실패함 |

기본 AgentLoop, 내부/예약 실행에서 같은 루프를 거치는 도구, SubagentManager의
도구 호출을 관찰한다. 각 실행에 별도 훅을 만들어 동시 대화 상태가 섞이지 않는다.
스킬 승인은 채팅의 정확한 대기 확인 응답, `/skill approve`, WebUI 승인/거절,
CLI `skill approve`의 성공 경로에서 기록한다. `source`로 경로를 구분하며, CLI/API
호출 주체가 실제 사람이라는 추가 인증을 제공하는 것은 아니다.

모델의 '승인받았다'는 문장이나 도구 인자의 주장은 승인 영수증을 만들지 않는다.
일반 자연어 요청 속 모든 승인을 자동 판독하지도 않는다. WebUI/CLI의 유효하지 않은
승인 요청은 승인 성공으로 기록하지 않는다. 채팅 확인 외의 프런트엔드에서 실패한
요청 전체를 수집하는 접근 로그 기능은 아니다.

AgentLoop/SubagentManager를 거치지 않는 외부 프로세스·직접 SDK Runner 호출,
MCP 서버 내부의 세부 동작, 실제 채널 전달 완료는 이 기록의 범위 밖이다.
과거 대화 전체를 소급 채점하거나 완전한 보안 감시·변조 방지 기록을 제공하지 않는다.

## 저장 내용과 장애 처리

저장하는 것은 시간, 도구 이름, 상태, 진입 경로, 실행/대화/호출/승인 대상의 해시
참조다. 명령 인자, 파일 내용·경로, URL, 메시지 본문, 도구 출력, 오류 원문,
승인 사유, 인증정보는 복제하지 않는다. 해시는 관련 기록을 연결하기 위한 것이며
완전한 익명화 수단은 아니다. 정확히 무엇을 보냈는지는 기존 권한 아래 원문 기록과
함께 확인해야 한다. 감사 기록 자체는 프롬프트나 기억 검색에 주입하지 않는다.

기본 보관량은 최근 10,000행이며 시도와 결과는 각각 한 행이다. 새 기록 추가 시
오래된 행부터 정리한다. 디렉터리/파일은 개인 권한으로 만들고 SQLite 잠금 대기는
50ms로 제한한다. 저장 장애가 실행을 막거나 재시도시키지 않도록 경고 후 계속한다.
비동기 도구 훅은 스레드 대기를 포함해 기록당 최대 200ms만 기다린다. 대기를 중단한
기록은 늦게 저장되거나 누락될 수 있으며, 이 시간 제한은 실제 도구 실행에는 적용하지 않는다.
따라서 저장 실패나 강제 종료 시 기록이 빠질 수 있다. 결과 행이 없는 시도는 성공이
아니며, 프로세스 강제 종료로 `unknown` 결과 행조차 쓰지 못할 수 있다.

```bash
.venv/bin/python -m pytest tests/agent/test_action_audit.py -q
```

실제 임시 파일 작업, 사전 거절, 변경 후 취소, 저장 장애, 동시 대화, 기록 상한,
본문 미저장, 기존 스킬 승인 경로를 검사한다. 프롬프트를 바꾸지 않으므로 이 단계는
실모델 평가를 추가하지 않는다.
