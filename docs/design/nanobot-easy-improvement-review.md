# nanobot-easy 보완안 코드 검토

검토일: 2026-11-16. 기준: `17b445e1` 및 검토 시작 시 작업 디렉터리에 있던 수정.
실행 중인 게이트웨이의 배포 상태를 감사한 문서는 아니다.

## 다섯 제안의 수정된 적용 방향

| 제안 | 현재 구현에서 확인한 사실 | 적용 방향과 이번 결과 |
|---|---|---|
| 완료 판단 | `runner.guard_final`, `task_note.final_check`, `SelectedContext.verdict`가 존재한다. 실제 답변 누락 보정, 보고 단계의 변경 차단, 실행 결과 참조 검사도 있다. task note와 context selection은 선택 기능이다. | 공통 검증 계층을 새로 만드는 제안은 보류한다. 일반 답변과 파일 변경의 완료 조건은 다르므로, 기존 경로별 반례를 먼저 검사한다. 이번에는 해당 집중 회귀 검사를 실행했으며 코어 루프를 변경하지 않았다. |
| 후속 지시와 기억 | 원문 이벤트, 작업 버전, 취소·명시적 재개, 읽기 범위·파일 버전 검사와 원문 검색이 이미 있다. | 의미 검색 추가에 앞서 최근 대화 누락부터 수정했다. 내부 복구 기록과 도구 결과가 대화 창의 개수를 소진하지 않도록 했다. |
| 응답 속도 | `context_trace` 및 provider 호출 관측으로 시도·복구·사용량을 기록한다. 기본 일반 경로와 선택적 단계별 추론/문맥 선택 경로가 있다. | 새 분류 모델이나 전역 강제 추론을 추가하지 않는다. 기존 계측으로 경로별 실제 모델 평가를 먼저 수행해야 한다. 이번 수정은 추가 LLM 호출을 도입하지 않는다. |
| 스킬 업무 성과 | 라우팅 회귀 검사는 검색 1위와 정답 스킬을 비교한다. `skill_decision`은 선택 관측이며 `gate_result` 없는 선택은 성공으로 집계하지 않는다. | 라우팅 정확도와 업무 완료율을 별도 지표로 유지한다. 이번에는 같은 trace의 재저장/결과 정정으로 통계가 부풀고, trace와 카운터가 따로 저장되는 결함을 수정했다. 최종 산출물의 품질을 자동 판정하는 기능을 추가한 것은 아니다. |
| 실행 상태 화면 | WebUI RuntimeSettings에 설정·워크스페이스 경로가 있고, OverviewSettings에 패키지 버전이 있다. 설정 API에는 재시작 관련 메타데이터가 있다. | 화면을 새로 만드는 제안은 축소한다. 후속 보완은 실행 프로세스의 소스 버전, 활성 기능, 시작 시 설정과 저장된 설정의 차이를 기존 화면에 연결하는 것이다. 디스크 설정을 곧바로 활성 상태로 표시해서는 안 된다. 이번에는 UI/API 계약을 변경하지 않았다. |

## 수정한 문제

### 최근 대화가 내부 기록에 밀려나는 문제

기존 `TaskContextStore.events(tail=N)`은 DB의 마지막 N건을 가져온 뒤 숨은 기록을
제외했다. 최근 2건이 내부 복구문과 사용자 후속 요청이면, 그 이전의 실제 답변을
복원하지 못했다. 또한 `minimal_input`은 마지막 80개 이벤트를 자른 뒤 대화만
골랐으므로, 도구 결과 90개 다음에 온 `Q2만 설명해줘`는 원래 Q2의 내용을 잃었다.

- 표시 가능한 이벤트 수를 기준으로 tail을 계산한다. 커서를 순회하고 필요한 수를
  확보하면 중단하므로 결과 전체를 메모리에 올리지 않는다.
- 설계용 최근 대화는 USER_MESSAGE/ASSISTANT_MESSAGE로 먼저 제한한다.
- 도구 자료의 단서는 별도 최근 이벤트 창에서 기존 최대 12건으로 유지한다.
- 소유자·워크스페이스·에이전트·세션·sequence·삭제 상태 필터를 유지한다.
- 기본값이 꺼진 context selection 기능을 켜거나, 다른 대화 경로를 교체하지 않는다.

숨은 기록이 아주 길면 필요한 대화를 찾기 위해 더 많은 DB 행을 검사할 수 있다.
모델 입력에 전체 과거 이력이나 도구 본문을 추가하는 변경은 아니다.

### 스킬 실행 기록과 통계의 불일치

기존 `record_trace`는 같은 trace ID를 덮어쓰면서 카운터는 매번 증가시켰다.
같은 성공 기록을 두 번 저장하면 trace는 1개인데 사용·성공 횟수는 각각 2가 됐다.
선택 → 성공 → 실패 정정도 여러 실행처럼 집계됐으며, 카운터 저장 실패 시 trace만
남을 수 있었다. 이 카운터는 검색 가중치에도 사용되므로 신뢰할 수 있어야 한다.

- 같은 ID를 갱신할 때 기존 통계 기여를 빼고 새 결과를 반영한다.
- trace와 카운터를 한 SQLite 쓰기 트랜잭션에서 저장한다.
- 스킬 재지정·선택 해제 시 이전 스킬의 기여도 정정한다.
- 선택만 한 기록은 여전히 성공/실패 미확인으로 남는다.
- 예전 부분 저장으로 카운터가 없는 trace를 정정해도 음수가 되지 않도록 한다.

DB 스키마 변경은 없다. 서로 다른 trace ID의 중복 실행을 자동 추정하지 않으며,
과거에 이미 부풀려진 통계를 자동 재계산하지 않는다. `gate_result=ok` 자체가
업무 품질의 독립 검증을 뜻하는 것도 아니다.

## 평가 기반 정리

인접 검증에서 스킬 로더의 기존 테스트 11개가 실제 저장소 시스템 스킬 9개까지
섞어 읽는 문제를 확인했다. 일반 스킬 단위 테스트는 `include_system=False`로
격리하고, 시스템 스킬 우선순위와 제외 동작은 별도 임시 디렉터리로 검증한다.
기억 평가 테스트가 현재 작업 디렉터리에 DB/보고서를 생성하는 것도 임시
디렉터리로 격리했다. 제품의 시스템 스킬 기본 동작은 바꾸지 않았다.

실제 모델 비교에 사용할 다음 24개 시나리오를 권장한다. 이는 평가 명세이며
이번에 실제 모델로 실행한 결과나 자동 채점 데이터셋은 아니다.

| 영역 | 사례 4개 | 확인할 결과 |
|---|---|---|
| 일반 답변 | 짧은 설명, 번역, 제공 문장 요약, 직전 답변의 표현 변경 | 불필요한 조회·설계 호출 없이 요청한 본문 전달 |
| 후속 지시 | Q2만 선택, 조건 하나 변경, 이전 방식 제외, 주제 전환 후 재개 | 최신 요구·참조 원문·다른 작업 경계 보존 |
| 기억 | 정확한 과거 원문, 바꿔 말한 질문, 최근 정정된 결정, 기록에 없는 질문 | 출처가 맞는 회상과 근거 없는 기억 주장 방지 |
| 파일 작업 | 지정 범위 검토, 여러 부분 읽기, 수정 후 검증, 외부에서 변경된 파일 | 대상·범위·버전·실행 결과와 답변 일치 |
| 중단/복구 | 도구 실행 전 취소, 실행 중 취소, 시간 초과, 결과 전달 실패 | 취소 반영·불확실성 표시·성공한 변경 재실행 방지 |
| 스킬 | 정확한 선택, 선택 불필요, 잘못된 선택 정정, 선택은 맞지만 결과 누락 | 라우팅 정답과 실제 산출물 완료를 분리 평가 |

동일 모델·설정·자료 스냅샷에서 기존 경로와 변경 경로를 비교하고, 성공한 사례만
골라 평균 내지 않는다. 요청 수신부터 최종 전달까지의 시간, 모든 시도/복구의 토큰,
필수 산출물 충족, 잘못된 완료 주장, 사용자 재설명 횟수와 중복 변경을 기록한다.
성공 기준을 사전에 정하고 질문·정답을 변경용/최종 평가용으로 나눈다.
